# 05 · 串口协议与上位机

> 这一节回答"上位机到底是什么"，以及上位机和 STM32 之间怎么说话
> 更新时间：2026-11-07

---

## 一、"上位机"到底是什么

你在智慧农业那套里用过它，只是叫法不同：

```
智慧农业：STM32 → ESP8266 → MQTT → 巴法云 → 小程序
                                          ↑
                                    这一层就是"上位机"
```

机械臂这边：

```
机械臂：摄像头 → 上位机（算视觉） → 串口 → STM32 → 舵机 + 滑台
                    ↑
              这一层是上位机
```

**它不是"回传数据 + 显示"那么简单。** 回传数据和显示只是顺带的，它真正干的活是：

| 上位机干的活 | STM32 干不了的原因 |
|---|---|
| **看摄像头，认出方块在哪** | F103C8T6 只有 64KB Flash / 20KB RAM，一张 640×480 的图就要 300KB，塞不下 |
| **算像素坐标 → 桌面毫米** | OpenCV 几十兆，跑不动 |
| **决定抓取顺序**（先抓哪个） | 同上 |
| **记日志、录像、给人看** | 没屏幕没存储 |

STM32 只干一件事：**收到坐标，把两个舵机和一个丝杆精确地挪过去**。

所以"上位机"= 一台跑视觉的电脑或开发板。

## 二、三种上位机方案怎么选

| | A. PC（Windows + Python） | B. 树莓派 / 嵌入式板 | C. 手机小程序 |
|---|---|---|---|
| **硬件成本** | 0（笔记本现成） | 150（零 2W）~ 600（4B） | 0 |
| **视觉能力** | 强，OpenCV 全功能 | 够用，帧率低些 | ✘ 跑不了，只能传云端，延迟 1~3 秒 |
| **演示形态** | 带笔记本 + 一根 USB 线 | 独立一台，插电就跑 | 手机遥控，做不了自动分拣 |
| **开发时间** | 最快，2~3 天 | 多 3~5 天（装系统、配环境、交叉编译） | 不能做主线 |
| **面试加分** | 一般（大家都这么干） | 加分（"一体化终端"） | — |

### 结论：**主线走 A，B 作为时间够就加的"第二形态"**

理由：
1. 12 月中旬投简历，只剩 5 周。B 光是配环境就要 3~5 天，不划算
2. 面试演示带笔记本是行业常态（就算用树莓派，也要带笔记本放 PPT）
3. 串口协议设计成**纯文本**，树莓派和 PC 发出来的字节完全一样，将来想换不用改 STM32

## 三、★ 但演示必须做两个版本

这是保底策略，别赌视觉一定能按时跑通：

| 版本 | 内容 | 什么时候能做 | 演示效果 |
|---|---|---|---|
| **V1 示教-复现** | 串口敲坐标 → 机械臂搬方块。坐标是事先量好的固定点 | **现在就能做，不动摄像头** | 稳定、可重复，"码垛"这件事本身就成立 |
| **V2 视觉分拣** | 摄像头看到方块 → 自动算坐标 → 抓 | 12 月初 | 亮眼，但现场打光一变就可能识别失败 |

**V1 就已经是一个能写进简历的项目了。** 简历上写"三轴 SCARA 码垛机械臂，逆运动学闭环误差 0.0001mm，回零重复精度 ±0.01mm"，比"用了个 YOLO"实在得多。

V2 是加分项，不是必需项。**顺序不能反。**

## 四、串口协议（纯文本，一行一条）

### 4.1 为什么先不上 Modbus RTU

Modbus 是对接 PLC 和组态软件的标准，写进简历算加分。但开发期用它很痛苦：

- 发一条命令要手算 CRC16，串口助手里没法直接敲
- 调一次坐标要开 Modbus Poll 之类的工具，改个值点半天

**所以：第一版用纯文本，协议层封成 `protocol.c` 一个文件。** 将来要换 Modbus，只改这一个文件的编解码，上层 `app_main.c` 一行不动。

简历上照样可以写"自定义指令协议，预留 Modbus RTU 接口"。

### 4.2 命令表（上位机 → STM32）

| 命令 | 格式 | 说明 | 例子 |
|---|---|---|---|
| 回零 | `H` | 滑台回原点，必须最先做 | `H` |
| 移动到平面坐标 | `M <x> <y>` | 保持当前 Z 和朝向，只动两个臂 | `M 180 60` |
| 升降 | `Z <mm>` | 只动滑台，0 = 原点 | `Z 80` |
| **设 Z 软上限** | **`ZL <mm>`** | **运行时改，掉电不存**，默认 80 | `ZL 150` |
| **限位自检** | **`L`** | **回显 `LIM 0/1`，装传感器/查线用** | `L` |
| **腕转** | **`W <0~180>`** | **转夹爪朝向**，90 = 中位 | `W 90` |
| 完整点位 | `P <x> <y> <z> [rot]` | 一次到位（先 Z 后 XY），rot 可选 | `P 180 60 50 90` |
| 夹爪 | `C <0/1>` | 0 = 张开，1 = 闭合 | `C 1` |
| 查询 | `S` | 返回位置和状态 | `S` |
| 使能 | `E <0/1>` | 0 = 松轴（手动摆臂），1 = 锁轴 | `E 0` |
| 标定 | `K <id> <us>` | 直接给某路舵机脉宽 | `K 0 1500` |
| 清故障 | `R` | 清除限位故障和错误状态 | `R` |

**`K` 的 id 对应：0 = 大臂，1 = 小臂，2 = 腕转，3 = 夹爪。**

### 4.3 响应（STM32 → 上位机）

| 响应 | 含义 |
|---|---|
| `OK` | 收到并接受（不代表已经动完） |
| `OK <n>` | 接受，附带数据 |
| `ERR <code>` | 拒绝，code 见下表 |
| **`POS <x> <y> <z> <wrist> <grip>`** | 查询结果，格式和 `P` 命令的输入对齐 |
| **`LIM <0/1>`** | 限位电平：0 = 释放，1 = 触发 |
| **`HOME UP / SEEK / RETREAT`** | 回零阶段播报（状态变化时才发一次） |
| **`HOME DONE Z0 <脉冲>`** | 回零完成，此处 Z=0；末位是触发点相对回零起点的脉冲偏移，用来判重复性 |
| `DONE` | 运动完成（如果开了完成回传） |

**`S` 的输出举例：`POS 137 137 0 90 1`** = 桌面 (137,137)mm、Z=0、腕转 90°、夹爪闭合。

里面有一步**正解反算**：STM32 只知道自己发了多少脉宽，要算出"现在末端在哪"，得把舵机角 → 关节角 → 桌面坐标过一遍 `fk_solve()`。

### 4.4 错误码

| code | 含义 | 上位机该怎么办 |
|---|---|---|
| 1 | 命令格式错 | 检查是不是少参数 / 多了空格 |
| 2 | 超出工作空间 | 换个坐标，或者提示"够不到" |
| 3 | 舵机行程不够 | 同上，一般是太靠边 |
| 4 | 电机忙 | 等 DONE 再发下一条，别连着灌 |
| 5 | 还没回零 | 先发 `H` |
| 6 | 限位故障 | 发 `R` 清掉，检查机械 |
| 9 | 回零失败 | 检查传感器和接线 |

★ **1~6、9 固件已全部实现**（11-16 核对）。`ERR 2` 现在同时覆盖两种情况：平面够不到 / Z 超出软上限（含负数，因为下面就是限位）。

### 4.5 三条铁律

1. **每条命令以 `\n` 结尾**，STM32 按行解析。别用 `\r\n` 以外的奇怪结尾
2. **发完一条等响应再发下一条**。STM32 是单线程的，连着灌会把缓冲冲掉
3. **运动是异步的**：`OK` 只表示"我收到了，开始动了"，不是"到了"。要么等 `DONE`，要么自己算时间

## 五、上位机示例代码（PC 端，Python）

```python
import serial          # pyserial
import time

ser = serial.Serial('COM3', 115200, timeout=2)

def cmd(s):
    """发一条命令，等一行响应"""
    ser.write((s + '\n').encode('ascii'))
    return ser.readline().decode('ascii').strip()

# 1. 连上先回零
print(cmd('H'))
time.sleep(8)                    # 回零大概 5~8 秒，等它走完

# 2. 抓一个事先量好的点
print(cmd('Z 120'))              # 先抬到安全高度
time.sleep(6)
print(cmd('M 180 60'))           # 平面移到方块正上方
time.sleep(3)
print(cmd('Z 45'))               # 降下来
time.sleep(4)
print(cmd('C 1'))                # 夹住
time.sleep(1)
print(cmd('Z 120'))              # 抬起
time.sleep(6)
print(cmd('M 120 -50'))          # 移到放料位
time.sleep(3)
print(cmd('Z 45'))
time.sleep(4)
print(cmd('C 0'))                # 松开
print(cmd('Z 120'))              # 抬走

ser.close()
```

**注意 `time.sleep` 的时间是粗估的**，实际用的时候应该改成"等 `DONE`"，或者干脆让 STM32 在 `OK` 后面直接带回预计耗时：`OK 3000` 表示 3 秒。

## 六、STM32 侧的解析思路

不用很复杂，`sscanf` 足够：

```c
// 收到完整一行后（已去掉换行），按第一个字符分派
char c = buf[0];                     // 看命令首字母
switch (c)
{
    case 'M':                        // M x y
        if (sscanf(buf + 1, "%f %f", &x, &y) != 2) return ERR_FORMAT;
        return cmd_move_xy(x, y);

    case 'Z':                        // Z mm
        if (sscanf(buf + 1, "%f", &z) != 1) return ERR_FORMAT;
        return cmd_move_z(z);

    case 'P':                        // P x y z
        if (sscanf(buf + 1, "%f %f %f", &x, &y, &z) != 3) return ERR_FORMAT;
        return cmd_move_xyz(x, y, z);

    case 'H':                        // 回零，无参数
        step_home_start();
        return 0;

    case 'S':                        // 查询
        printf("POS %.1f %.1f %.1f %d\n", ...);
        return 0;

    default:
        return ERR_FORMAT;           // 不认识的命令
}
```

**接收用轮询不用中断**：主循环里 `HAL_UART_Receive(&huart1, &ch, 1, 0)`（超时 0），收到一个字节就攒进缓冲，收到 `\n` 就解析。115200 下一个字节 87μs，主循环转得比这快得多，不会丢。

**★ 不要在中断里做 `sscanf` 和浮点运算。** 解析全在主循环里做。

## 七、一个容易忽略的点：`printf` 重定向

Keil AC5 里重定向 `printf` 到串口，要重写 `fputc`：

```c
#include <stdio.h>

int fputc(int ch, FILE *f)
{
    uint8_t c = (uint8_t)ch;                       // 转成字节
    HAL_UART_Transmit(&huart1, &c, 1, 10);         // 发出去，10ms 超时
    return ch;                                     // 返回原字符，告诉库发成功了
}
```

**但这样发一条带小数点的 `printf` 会阻塞几百 μs。** 在控制循环里频繁 printf 会拖累时序。建议：

- 调试期可以随便 printf
- 正式跑的时候把 printf 关掉，只在"查询状态"时输出

**★ ARMCC 编译中文串会报 `#8: missing closing quote`。** 所有 `printf` 的内容一律用英文，别写中文。要输出中文只能上 OLED，而且那又是另一套坑。

## 八、主循环长什么样（伪代码）

```c
void app_loop(void)
{
    // 1. 收串口字节，攒够一行就解析
    app_uart_poll();

    // 2. 20ms 节拍：舵机慢慢挪、状态机推进
    if (HAL_GetTick() - s_last_tick >= 20)
    {
        s_last_tick = HAL_GetTick();
        servo_update();
        step_home_poll();
    }

    // 3. 限位故障要停机报警
    if (step_limit_fault())
    {
        step_stop();
        // 可以在这里闪 LED 或者蜂鸣
    }
}
```

**★ 整个循环里不许出现 `HAL_Delay()`。** 一旦 Delay，串口就收不到命令，舵机也不平滑了。所有等待都改成查 `HAL_GetTick()` 的时间戳。
