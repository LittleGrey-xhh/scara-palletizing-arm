# 12 · V1 平面搬运：把一条坐标序列跑成完整动作

> 前面十一篇都在解决「单个轴能不能动、动得准不准」。
> 这一篇解决最后一件事：**让四个舵机加一根丝杆，按一条写死的序列，把一个东西从 A 搬到 B。**

## 一、这一步要验证什么

单轴验收只能证明每个轴各自听话，不能证明它们合起来能干活。V1 的目标是一个可演示的最小闭环：

```
坐标 (x,y,z) → 逆解 → 大臂 + 小臂 + 腕转 + Z 同步到位 → 夹爪开合 → 搬运成立
```

判据只有一条：**东西从 (100,0) 搬到 (200,0)，落点误差在 5mm 内。**

选择「示教-复现」而不是「自主规划」，是个刻意的取舍：

| 方案 | 需要什么 | 风险 |
|---|---|---|
| 示教-复现（V1 采用） | 手动走一遍，记下命令，回放 | 换位置要重录，但不需要任何感知 |
| 视觉分拣（V2） | 相机 + 标定 + 目标检测 | 任一环节不稳，整个演示崩 |

V1 先把「控制链路是通的」这件事钉死，视觉才有意义。**没有 V1 的 V2 只是在赌。**

## 二、上位机：三个阶段

`tools/arm_teacher.py` 一共两种运行模式，覆盖示教-复现全流程。

```bash
python arm_teacher.py                # 交互模式：手动发命令，可边操作边记录
python arm_teacher.py demo_seq.txt   # 回放模式：按文件自动执行
```

交互模式里有三个元命令，不属于串口协议，只在上位机生效：

| 命令 | 作用 |
|---|---|
| `rec` | 清空缓冲，开始记录。之后每条命令自动追加一条 `!3` |
| `save` | 把缓冲写成 `demo_seq.txt`，每行一条 |
| `q` | 退出 |

任何一行输入不是这三个，就当串口命令原样发出去（`M 180 60`、`C 1`、`S` 都可以）。
`!n` 在上位机解释成「等 n 秒」，固件根本看不到它。

**为什么要有 `rec` 而不是直接手写序列**：手写序列的时候人是「想象」机械臂怎么动，
录出来的东西必然漏步、等错时间。示教的价值就是把「实际动了几秒」变成数据，
而不是靠猜。

## 三、序列格式

```
# 注释行，回放时跳过
H            命令：原样发到串口
!8           等待 8 秒
```

就两条语法。极简是有意的——序列文件是给人改的，语法越少越不容易改错。

`tools/demo_seq.txt` 是现成的平面搬运模板：

```
H          !8      回零（必须在第一条）
HM         !4      舵机回上电收拢位
Z 50       !6      抬到安全高度
M 100 0    !3      到抓取点上方
Z 5        !6      降到抓取高度
C 1        !3      闭合夹爪
Z 50       !6      抬起
M 200 0    !3      平移到放置点上方
Z 10       !6      降到放置高度
C 0        !3      张开夹爪
Z 50       !6      抬起
HM         !4      回待机
```

## 四、★ 等待时间是算出来的，不能拍脑袋

这是整条序列里最容易翻车的地方，也是「录完就能跑」和「录完半空合爪」的区别。

| 步骤 | 耗时来源 | 给多少 |
|---|---|---|
| `H` 回零 | BACKOFF 0.5s + SEEK（深度随起点变，5mm/s）+ RETREAT 0.3s | **`!8`** |
| `Z` 升降 | 10mm/s（4000Hz × 0.0025mm），45～50mm ≈ 4.5～5s | **`!6`** |
| `HM` 回待机 | 3 秒斜坡 | **`!4`** |
| `M` 平移 | 65mm 约 1.5s（舵机 1.5°/拍 × 20ms 节拍 = 75°/s） | `!3` |
| `C` 夹爪 | 两段式：过冲 + 回退，约 1s | `!3` |

三条硬规则：

**1. `H` 必须是第一条，而且不能省。**

串口一打开 MCU 就复位 —— CH340 的 DTR/RTS 接在 NRST 上，这是硬件行为，不是软件 bug。
复位后 `s_homed = 0`，任何 `Z` 命令都会直接 `ERR 5`。

**2. `H` 后面必须等足，因为 `s_homed` 只在 `HOME DONE` 那一拍才置 1。**

不是「收到 H 就置 1」。早发 `Z` 一样 `ERR 5`。所以 `!8` 不是保险，是必须。

**3. Z 的速度定死在 10mm/s 是有原因的。**

早期 20mm/s 时，`Z` 到位瞬间的冲击让整个立柱晃，夹爪跟着荡，落点误差直接翻倍。
降到 4000Hz（10mm/s）之后晃动肉眼不可见。**代价是每一段 Z 要等 5 秒，序列总时长 75 秒左右。**

## 五、★ 抓取 Z=5、放置 Z=10，这 5mm 是故意的

看起来像是笔误，其实是补偿。

臂满伸时末端下坠约 30～40mm（`docs/11` 里那条结构性限制）。这个下坠是**确定性**的：
同样的指令、同样的姿态，下垂量一样。所以：

- **抓取**用 `Z 5`：夹爪实际比指令低，正好能咬住地上的物体
- **放置**如果也用 `Z 5`：夹爪实际会比台面低 5mm，**直接顶到台面**，要么夹爪被顶开、要么 Z 丢步

所以放置抬高到 `Z 10`，让实际落点刚好贴着台面。

★ 注意这个补偿是**姿态相关**的，不是全局常量。换到 r 更小的位置抓取，下垂量变小，
`Z 5` 可能就够不着了。这正是不做「下垂补偿表」的原因（见 `docs/11` 末尾）——
V1 只在一个固定工作点上跑，同指令同下垂，误差自洽。

## 六、实测结果（11-23 更新）

早先那一版记录的是「落点误差 5mm」，但那个数**口径有问题**，11-23 重测后校正如下。

| 项 | 结果 |
|---|---|
| 落点偏差 | **±4mm**（4 次：9.6 / 10.0 / 10.4 / 9.8 cm，台面标定板读数） |
| 补偿前偏差 | 15mm（指令 100mm 实走 85mm） |
| 单次周期 | 约 75 秒（瓶颈是 Z 的 5 秒 × 6 段） |
| 腕转解耦 | 五点实测与公式误差 < 1°（见 `docs/10` 第五节） |
| 严格重复性 | **仍未验收**，见下节 |

★ **为什么不能直接叫「重复定位 ±4mm」**：4 次只记录了落点，没有逐次记录起点摆位，
8mm 的极差里混着人工回位偏差；而且用的纸巾是圆弧边，读数本身有 ±3mm 噪声。
要出严格重复性，必须换成直角边的方块，并且两头都记。

### 6.1 ★★★ 末端下垂：行程按比例缩水 15%

`M 100 0` → `M 200 0` 指令走 100mm，实测只有 **85mm**。逆解、正解、`S` 回显全都自洽
（`POS 79/160/60` 一路吻合），但物理就是走不够。

**根因**：臂下垂时夹爪不是竖直向下，而是**朝回转中心倾斜**。夹爪是根约 120mm 的杠杆，
倾斜 β 时爪尖横向偏移 `120·sin β`。r 越大、臂越直、下垂越狠、β 越大 —— **越往外偏得越多，
行程看起来就按比例缩短**。

**为什么一直没查出来**：`S` 回显用的是软件跟踪角度 `cur_deg` 做正解，
**和逆解互为反函数，永远自洽，对物理位置零信息**。`S` 回得准 ≠ 真走准了。

实测（标定板 0 刻度对齐 `M 80`）：

| 指令 | 板刻度 | 指令 | 板刻度 |
|---|---|---|---|
| `M 80` | 0 cm | `M 198` | 10.0 cm |
| `M 100` | 1.8 cm | `M 222` | 11.5 cm |
| `M 137` | 5.0 cm | `M 225` | 12.0 cm |

换算系数递减（50～100mm 段 0.82、100～120mm 段 0.74），**是非线性的**。

**处置**：序列里把放置点从 `M 200 0` 改成 `M 224 0`，黑盒补偿。
★ 补偿必须沿**径向** —— 偏移方向朝回转中心，走 Y 或斜线时会跟着转，V2 前必须改成矢量补偿。

### 6.2 ★★ 补偿标定在悬挂态，接触台面会被削弱

上面的补偿是在**末端悬空**时标定的。物体一旦接触台面，地面反力会从末端传回舵机，
抵消一部分下垂、减小倾斜角，**实际需要的补偿量就变小了**。机制上成立。

**但它引出一个无解的矛盾（这条实测确认）：**

| 状态 | 落点稳定 | 补偿有效性 |
|---|---|---|
| 完全悬空 | ✘ 实测 `Z 25` 张爪，纸巾直接翻倒 | ✔ 完整 |
| 轻压 1~2mm | ✔ 实测 `Z 24` 姿态稳定 | ✘ 被削弱 |

**鱼与熊掌。V1 选「轻压 1~2mm」，稳定优先** —— 演示视频里没人看得出差几毫米，但物体翻掉就穿帮。

当前可用配置（实测 4 次）：`Z 34` 轻压 1mm、放置点 `M 224`，纸巾左边缘读数 96~104mm，**偏差 ±4mm**。

> ⚠ **量化数据待补**：11-23 曾想测「悬空 / 轻压 / 重压」三状态的位移差，但当时**混用了两套测量
> 参照物**（早期量空爪位置、后期量物体边缘），推出的差值全部作废。要拿真数据必须换直角边方块
> + 统一参照物重做对照。

**Z 值必须按"触地点"实测**（物体底部刚碰台面的 Z 指令值），不能沿用手册值：

| 位置 | 触地点 Z | 采用 Z（−1，压下 1mm） |
|---|---|---|
| `M 100` | ≈16 | 15（抓取） |
| `M 158` | 25 | 24（实测姿态最稳） |
| `M 224` | 35 | 34（放置） |

每往外 66mm 半径，触地点抬高 10mm（下垂斜率 0.15mm/mm，与水平偏移斜率 0.18 同量级）。

腕转解耦在这一步得到实战验证：`M 100 0` → `M 200 0` 平移 100mm，夹爪朝向肉眼无变化，
方块不歪、不掉角。**如果没做解耦，这个搬运根本跑不成** —— 腕转向量会从 83° 一路漂到 117°，
到 200mm 处夹爪已经歪了 34°，一夹就是夹棱。

## 七、还没验收的：重复性

**这一项必须说清楚，不能拿「跑通了一次」冒充「稳定」。**

同一套序列跑 3 遍，每遍把物体放回 (100,0)，量落点偏差的方向和大小：

| 现象 | 结论 | 处理 |
|---|---|---|
| 三次同方向、同大小 | 系统误差 | 改序列坐标补掉（`M 200 0` → `M 196 0`） |
| 每次方向不同 | 随机误差 | 查夹持滑移、起手姿态、Z 丢失步 |
| 越跑越偏 | 时钟性漂移 | 查舵机齿轮间隙、丝杆丢步 |

★ **不需要方格标定板。** 标定板解决的是绝对定位（落点相对世界坐标的偏差）；
重复性只看三次落点**彼此之间**的间距和方向，纸上画个十字 + 钢尺量三个记号就够。

这是这个项目当前唯一没做的验收项，也是简历上「5mm」这个数字目前只能写「单次」的原因。

## 八、这一步教了什么

### 序列的鲁棒性 = 每一步的等待时间都对

一条序列里任何一处的 `!n` 给小了，故障现象都会出现在**后面几步**。
半空合爪看起来像「夹爪坏了」，实际是 `Z 50` 没走完就发了 `C 1`。

**排查顺序永远是：先怀疑时序，再怀疑硬件。**

### 状态机的置位点决定等待时间

`s_homed` 在 `HOME DONE` 那一刻才置 1，不是在收到 `H` 那一刻。
只要有一处状态是「异步完成」的，等待时间就必须按**完成时刻**算，不能按**发出时刻**算。

同一个道理在 `step_move_to_mm` 上又来了一次：Z 还在动的时候发 `M`，`ERR 4` 直接拒。
**所有「会动」的命令，等待时间都属于协议的一部分。**

### 演示优先于完美

这台机器满伸会前倾、末端下坠 2 指宽、Z 只有 70mm 行程。
按教科书标准它不合格，但它能在一个固定工作点上重复搬运 5mm 精度 —— 演示成立。

**先让一个闭环完整跑通，再谈精度。** 反过来做，永远在调单轴，永远没有可展示的东西。
