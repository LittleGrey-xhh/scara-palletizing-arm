# 07 · 舵机到底是怎么"定位"的

> 回答三个问题：我的舵机是不是最低级？没有回传怎么办？怎么保证转到位？
> 更新时间：2026-11-09

---

## 一、先纠正一个误解：MG996R 是**数字舵机**，不是模拟

三个证据：

1. 说明书原文：`舵机类型：数字舵机`
2. 实物标签：`MG 996R` / **`DIGI`** `HI TORQUE` —— DIGI 就是 Digital
3. 死区 4μs —— 模拟舵机做不到这么小（典型 5～10μs）

### 模拟 vs 数字，差在哪

```
模拟舵机：
  PWM → RC 滤波（变成模拟电压）→ 比较器 ← 电位器
                                   ↓
                              电机驱动 → 电机 → 齿轮 → 输出轴
                                                        ↓
                                                     电位器
  纯硬件，没有 MCU，采样率 = PWM 频率 50Hz

数字舵机：
  PWM → 内部 MCU（采样 + PID）→ H 桥 → 电机 → 齿轮 → 输出轴
              ↑                                        ↓
              └──────────── 电位器 ←──────────────────┘
  有 MCU，内部采样 300Hz 以上，死区小、保持力强、响应快
```

**但两者的本质是一样的：都是位置闭环。**

---

## 二、★ 关键认知：舵机内部本来就是闭环的

这是最容易被误解的一点。很多人以为"PWM 舵机是开环"，**错了**。

```
你给 1.5ms  ────→  舵机内部：目标位置 = 中位
                        ↓
                    和电位器的实际值比较
                        ↓
                    有偏差？→ PID 算 → H 桥 → 电机转
                        ↓
                    转到偏差为 0 才停
```

**舵机自己会一直调到"电位器反馈 = PWM 目标"为止。** 你根本不用管它怎么转、转多快、要不要减速——那是它内部 PID 的事。

所以：

| 说法 | 对不对 |
|---|---|
| "舵机是开环的" | ✘ 错，内部是闭环 |
| "舵机不需要编码器" | ✔ 对，电位器就是它的编码器 |
| "我不知道它实际在哪" | ✔ 对，**对外没有回传** |
| "我发的角度它一定能到" | ✔ 只要不超载、不堵转、电源够 |

**准确的说法是：舵机内部闭环，对外单向（只收不发）。**

这就是为什么说它"低级"——不是定位能力差，是**不能把状态告诉你**。

## 三、和总线舵机 / 步进 / 伺服的真实差距

| | **MG996R**（我们） | 总线舵机（如 LX-16A） | **步进**（我们滑台） | 工业伺服 |
|---|---|---|---|---|
| 内部反馈元件 | 电位器（模拟） | 磁编码器 12 位 | **无** | 光电编码器 17～23 位 |
| 内部闭环 | ✔ | ✔ | **✘ 真开环** | ✔ |
| **对外回传位置** | **✘** | **✔** | ✘ | ✔ |
| 回传还能给什么 | 无 | 位置/温度/电压/负载 | 无 | 全套 |
| 角度分辨率 | 约 0.36°（死区） | 0.088°（4096 线） | — | 极高 |
| 重复精度 | ±1～2° | ±0.5° | **开环，不确定** | ±0.001° |
| 接口 | PWM 单线 | 串行总线，一根线串几十个 | 脉冲+方向 | 总线/脉冲 |
| 单只价格 | **15 元** | 100～200 元 | 60 元 | 1000 元+ |

**看清楚这张表的一个反直觉结论：**

**我们的步进电机（滑台）才是真开环的那个，舵机反而是内部闭环的。**

| 轴 | 丢位风险 | 会不会自己纠回来 |
|---|---|---|
| **Z 滑台（步进）** | 高速失步、堵转、超载 | **不会**，丢了就永远差那么多 |
| **θ1/θ2/腕转（舵机）** | 齿轮打滑、严重堵转 | **会**，只要脉宽不变，它自己会转回去 |

所以步进电机才需要**限位开关 + 回零**，舵机反而不需要（但要标定脉宽↔角度的对应）。

## 四、怎么保证舵机转到"特定角度"

**只需要四件事，其中只有一件是软件能管的。**

### 4.1 脉宽要准（软件管）

```
72MHz → PSC=71 → 1MHz 计数
CCR = 1500 就是 1500μs，误差 ±1 个计数 = ±1μs = ±0.09°
```

定时器给的脉宽精度远高于舵机能分辨的（死区 4μs）。**这一项不是瓶颈。**

### 4.2 电源要稳（硬件管）

MG996R 堵转 2.5A。如果电源带不动，电压跌到 4V 以下，**扭矩直接掉一半**，该到 90° 的只到 70°，而且它自己以为到了（因为电位器还没到，但电机已经没力了）。

**这就是为什么舵机电源必须独立、线要粗、要并大电容。**

### 4.3 负载别超（设计管）

臂长了、重了、弯矩大了 → 舵机顶着转不到目标 → 一直"嗡嗡"较劲 → 发热 → 烧。

**这是我们的主要风险**（9.9 kg·cm 的悬臂弯矩）。

### 4.4 机械别卡（装配管）

任何干涉都会让它永远到不了位。表现是持续嗡嗡响 + 外壳发烫。

## 五、那我们说的"闭环"和"开环"到底指什么

完整系统里其实有三层：

```
第一层：舵机内部闭环    电位器 → PID → 电机        ✔ 有（我们管不了）
第二层：控制器知道末端在哪   STM32 有没有位置反馈     ✘ 没有（舵机不回传）
第三层：整个系统能自我纠错   视觉/编码器 → 修正指令    ✘ 第一版没有
```

**我们缺的是第二层和第三层。**

### 5.1 第二层缺失的影响

STM32 只知道"我发了 90°"，不知道"它真到了 90°"。

如果中间出了事（舵盘滑齿、齿轮崩了、线断了），**STM32 完全不知道，还会继续按"已经在 90°"往下算**——后面的坐标全错。

**兜底办法：**
- 每次上电先回中位（发 1500μs），让舵机回到已知姿态
- 标定表记录"脉宽 ↔ 实际角度"，装配时用卡尺和量角器实测
- 演示前肉眼确认一次

### 5.2 第三层缺失的影响

抓取偏差 ±3～5mm 没法自己修正。

**兜底办法（P2 再做）：**
- 摄像头看末端实际位置 → ArUco 标记 → 修正指令
- 这是"视觉伺服"，不用改硬件

## 六、那"初始化"到底要做什么

**舵机不需要初始化。** 它上电后自己去读电位器、自己找位置。

需要初始化的是**我们这边的认知**：

| 要做的 | 为什么 |
|---|---|
| 上电发 1500μs 让所有舵机回中位 | 断电期间位置可能被外力推动过，回到已知姿态才能算坐标 |
| **标定每个舵机的"脉宽 ↔ 机械角"** | 舵机只知道"电位器 30%"，不知道"机械臂转了 45°"，这个翻译关系要测 |
| **标定机械干涉边界** | 有些角度机械上撞得到，必须禁掉 |
| 记录 `SERVO_DIR` | 舵机装反了，脉宽加角度减，要标出来 |

**"标定"不是给舵机做初始化，是给我们的坐标系建映射。**

## 八、舵机接线（三线，但电源是重点）

```
     舵机线（JR/FUTABA 通用插头）
     ┌─────────────────┐
     │ 棕/黑   红   橙  │
     │  ↓      ↓    ↓  │
     │ GND   5~6V  PWM │
     └─────────────────┘
              │    │    │
              │    │    └─→ STM32 PWM 引脚（PA0/PA1/PB8/PB6）
              │    └──────→ 降压模块 CH1（调到 6.0V）
              └───────────→ 公共 GND（★ 必须和 STM32 共地）
```

**三条铁律：**

1. **红（中间）= 电源，不是信号。** 插反了舵机瞬间烧。
2. **舵机电源绝对不能从 STM32 板取。** 堵转 2.5A，板子的 5V 稳压器最多 500mA，一堵转整块板复位。
3. **信号线（橙）直接接 GPIO 就行**，不用串电阻、不用电平转换——舵机信号输入是高阻，3.3V 完全够。

**四个舵机的电流预算：**

```
空载转动：100mA × 4 = 400mA
正常动作：300mA × 4 = 1.2A
静止保持：50~150mA × 4 = 600mA 以内
单个堵转：2.5A
```

**降压模块 CH1 是 3A，所以：**
- 四个同时正常动作 1.2A，够
- 两个同时堵转 5A，超过，会掉压
- **四个同时堵转 10A 是理论极值，实际不会出现**（详见第九节）

**这就是 `servo_move_deg()` 为什么要"慢慢转"的另一个原因**——不是怕甩，是怕四个同时启动的浪涌把电源拉垮。

## 九、★ 保持 ≠ 堵转：这两件事的电流差 20 倍

### 9.1 先纠正一个常见误解："转到角度就停止输出"

**舵机转到目标角度后，电机并没有断电。**

```
误差 = 目标位置 − 电位器实际位置

误差 = 0   →  PID 输出 0  →  电机不转，但线圈一直通电待命
误差 ≠ 0   →  PID 输出   →  电机立刻出力把误差拉回 0
```

**所以舵机是"一直在岗"，不是"到位就下班"。** 这叫**保持力矩（holding torque）**。

**★ 一旦停掉 PWM 信号，舵机会立刻松掉。** 因为舵机判断"没有控制信号"= 无人管我 = 我不用保持。

有些舵机是 1～2 秒后松，MG996R 是很快就松。**所以代码里绝对不能 `HAL_TIM_PWM_Stop()`**，只能改 CCR。

### 9.2 保持和堵转的区别：看有没有"误差"

| 状态 | 目标 vs 实际 | 电机 | 电流 | 发热 |
|---|---|---|---|---|
| **静止保持** | 误差 = 0 | 不转，待命 | **50～150mA** | 不热 |
| **正常转动** | 误差在缩小 | 转 | 100～300mA | 微温 |
| **启动加速** | 误差突然变大 | 猛转 | 1～1.5A，几十毫秒 | 不热 |
| **保持但被外力推** | 误差小，推不动 | 顶着 | 300mA～1A | 温热 |
| **堵转（顶死）** | 误差大，永远消不掉 | 死顶 | **2.5A 持续** | **烫手，会烧** |

**判据就一条：目标角度和实际角度之间有没有一个消不掉的误差。**

- 到了目标位置，没外力 → 误差 0 → **保持，小电流**
- 到了目标位置，但机械卡住/负载超了 → 误差消不掉 → **堵转，大电流**

### 9.3 那四个舵机同时堵转会出现吗

**主人说得对，正常动作时不会。** 会同时堵转只有三种情况：

| 场景 | 会不会 | 说明 |
|---|---|---|
| 静止在某角度 | ✘ | 保持状态，4 × 100mA |
| 匀速转动 | ✘ | 4 × 300mA |
| **上电瞬间四个一起找中位** | **✔ 会** | ★ 真风险。断电时位置随便，一上电四个同时大扭矩转回去 |
| 夹爪咬住物体 + 臂在加速 | ✔ 部分 | 两个同时高负载 |
| **代码 bug 导致超程** | ✔ 会 | 四个一起顶机械限位 = 四个 2.5A |
| 负载超过舵机扭矩 | ✔ 会 | 我们的悬臂弯矩就是这个风险 |

**"4 × 2.5A = 10A"是理论极值，只在极端 bug 下出现。** 但**上电瞬间**这条是真会发生的，所以：

- `servo_init()` 里先写 CCR 再启动 PWM，让第一个周期就是正确脉宽，减小冲击
- 四个舵机先后启动（中间隔 100ms），别让浪涌叠在一起

### 9.4 ★ 唯一"长时间大电流"的场合：夹爪咬合

夹爪咬住物体时，是**持续出力**维持咬合力：

```
咬合力需求 5N，力臂 30mm → 需要 0.15 kg·cm
MG996R 有 9.4 kg·cm，所以只需要出 1.6% 的力
→ 电流很小
```

**实际上夹爪的电流取决于"咬多紧"，不是"有没有咬"。**

| 夹爪状态 | 电流 |
|---|---|
| 张开 / 空合（合到底没东西） | 100～300mA |
| 咬住 40mm 木块 | 300～800mA |
| 咬住太厚的东西（卡住合不到位） | **1.5～2.5A，会烫** |

**所以夹爪要留余量：** 夹爪开合的行程要设成"物体尺寸 + 2～3mm"，让它合到位后还能继续走一点（产生咬合力），但**不能差太多**，否则就是长时间堵转。

**判断夹爪有没有过紧：** 咬住后摸舵机壳，温热正常，烫手就是咬太紧了，要把闭合位的角度往回退几度。

### 9.5 想要"锁死角度"，该怎么做

**什么都不用做，保持送固定脉宽就行。**

```c
// 正确的"锁死"：一直送信号，只改 CCR
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 1500);   // 一直 1500μs
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);              // 启动后永不 Stop

// 错误的"锁死"：停掉 PWM
HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_1);   // ★ 舵机立刻松掉，臂会掉下来
```

我们在 `servo_init()` 里启动 PWM 之后就再没停过，`servo_set_deg()` 只改 CCR——**这就是正确的"锁死"方式，不需要额外操作。**

**唯一能真正"松轴"的办法是断舵机的电**（不是断信号，是断 6V 电源）。但那样臂会因为重力/惯性掉下来，除非先把它放到安全位置。

> **注意区分：** 代码里 `E 0` 是让**步进电机**（滑台）松轴，不是舵机。舵机没法用软件松轴，MG996R 不支持这个功能（有些高端舵机能设"松轴模式"，这颗不行）。

### 9.6 一句话结论

| 问题 | 答案 |
|---|---|
| 转到角度后会停止输出吗 | ✘ 不会，一直在通电保持 |
| 保持时电流高吗 | ✘ 不高，50～150mA（堵转的 1/20） |
| 怎么锁死角度 | **持续送固定脉宽**，别停 PWM |
| 4 个会同时堵转吗 | 正常动作不会，但**上电瞬间会** |
| 哪里真会长时间大电流 | **夹爪咬太紧** + 机械卡死 + 超载 |

## 十、舵机转速怎么控制

### 10.1 核心认知：PWM 舵机不能"设速度"，只能"设位置"

舵机内部是位置闭环，你给目标角度，它就用内部最大速度冲过去。**没有任何一根线能告诉它"慢点"。**

想慢，只有一招：**把大目标拆成小步，一步一步给。**

```
想要 2 秒转 60°：
  不是发一个"转 60°"的脉冲
  而是每 20ms 发一次新的目标：90° → 90.6° → 91.2° → … → 150°
  共 100 次，每次只加 0.6°
```

**舵机本身没变，是我们"喂目标"的节奏变慢了。**

### 10.2 我们的两套接口

```c
// 方式一：指定最大速度（度/拍，20ms 一拍）
servo_move_deg(SERVO_ARM1, 150.0f, 0.6f);    // 0.6°/拍 = 30°/s

// 方式二：指定总耗时（毫秒），内部自动算速度 ★ 推荐
servo_move_time(SERVO_ARM1, 150.0f, 2000);   // 2 秒转过去
```

`servo_move_time()` 内部就是 `dist / (ms/20)` 算出速度，再转给 `servo_move_deg()`。

**速度上限 7°/拍 = 350°/s**，这是 MG996R 的物理极限（0.17s/60°），设更快它也跟不上，只会变成"台阶式"抖动。

### 10.3 ★ 光慢还不够，还得有加减速

如果每拍固定走 0.6°，那就是**匀速**：启动瞬间速度从 0 突变到 30°/s，停止瞬间从 30°/s 突变到 0。末端还是会"顿一下"。

**所以加了梯形加减速**：速度不是恒定的，而是"加速 → 匀速 → 减速"。

```c
// 用 v² = 2·a·s 反算：剩这么点距离，最多能跑多快
v_allow = sqrtf(2.0f * SERVO_ACCEL * dist);
if (v_allow > step_max) v_allow = step_max;

// 让速度的变化受加速度限制，加减速段就出来了
if (v_allow > step + SERVO_ACCEL)      step += SERVO_ACCEL;   // 加速
else if (v_allow < step - SERVO_ACCEL) step -= SERVO_ACCEL;   // 减速
else                                    step  = v_allow;
```

**这个公式的物理意义：** 剩余距离越短，允许速度越低——自动在快到目标时减速，不会冲过头。

### 10.4 实测曲线（`pc_test/test_servo_speed.c`）

设 2 秒转 60°：

| 拍数 | 角度 | 速度(°/拍) | 等效(°/s) | 阶段 |
|---|---|---|---|---|
| 1 | 90.15 | 0.150 | 7.5 | 加速 |
| 2 | 90.45 | 0.300 | 15.0 | 加速 |
| 3 | 90.90 | 0.450 | 22.5 | 加速 |
| 4 | 91.50 | 0.600 | 30.0 | 加速结束 |
| 5～100 | … | 0.600 | 30.0 | **匀速** |
| 101 | 149.4 | 0.6 | 30.0 | 开始减速 |
| 103 | 150.00 | 0.011 | 0.5 | 减速结束 |

**实际用时 104 拍 = 2.1 秒（设定 2.0 秒，误差 5%）。**

对比：同样 60°，设最大速度 1.5°/拍（75°/s）→ **46 拍 = 0.9 秒**。

### 10.5 参数怎么调

`servo.c` 顶部三个宏：

```c
#define SERVO_STEP_MAX   1.5f    // 默认最大速度，75°/s
#define SERVO_STEP_MIN   0.15f   // 最低速度，3°/s
#define SERVO_ACCEL      0.15f   // 每拍速度增量，0→1.5 要 10 拍 = 0.2s
```

| 想要的效果 | 改哪个 |
|---|---|
| 整体更慢 | 调小 `SERVO_STEP_MAX`，或者用 `servo_move_time()` 直接给时间 |
| 起步更柔和 | 调小 `SERVO_ACCEL` |
| 停止不顿 | 调小 `SERVO_ACCEL`（减速段更长） |
| 太磨蹭 | 调大 `SERVO_ACCEL` |

**注意：`servo_move_time()` 算的是匀速值，加了梯形后实际会慢 5～20%。** 对演示够用，要精确就自己在 `SERVO_ACCEL` 上补。

## 十一、PWM 超出行程会怎样

### 11.1 后果：顶死 → 堵转 → 2.5A → 烫 → 烧

舵机内部有**机械限位挡块**，转到头就转不动了。但如果 STM32 还在发"继续转"的脉宽：

```
目标 3000μs（想转 225°）
  → 舵机内部顶到机械挡块，实际只能到 ~185°
  → 电位器读回来的值 < 目标值
  → 误差一直存在，消不掉
  → PID 输出饱和，电机全力顶住挡块
  → 堵转电流 2.5A 持续
```

**时间线：**
- 几秒：外壳明显发热
- 30 秒：烫手（60～70°C）
- 几分钟：齿轮变形、电机绕组烧毁、塑料件熔化

### 11.2 我们的三层保护

| 层 | 在哪 | 做什么 |
|---|---|---|
| 第 1 层 | `servo_deg_to_us()` | `clampf(deg, 0.0f, 180.0f)` —— 角度先夹在 0～180 |
| 第 2 层 | `servo_set_us()` | 夹到 `[us_min, us_max]` —— 脉宽再夹一次（标定后的真实安全范围） |
| 第 3 层 | `kinematics.h` | `SERVO1_MIN_DEG = 8 / MAX = 172` —— 逆解算出来的角度再留 8° 余量 |

**所以正常路径下，无论怎么算都不会超。**

**唯一能突破的是标定命令 `K <id> <us>`**（`servo_set_us_raw` 绕过了第 2 层），但它自己有硬限制：

```c
if (b < 400 || b > 2600) { printf("ERR 2\r\n"); break; }   // 标定时允许略超，但不能离谱
```

### 11.3 还有两个陷阱

**陷阱一：PWM 停掉 = 舵机松掉**

```c
HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_1);   // ★ 臂会掉下来
```

不是"超行程"，但同样是事故。我们的代码启动 PWM 后**再没停过**。

**陷阱二：上电瞬间 CCR 是垃圾值**

CubeMX 生成的 `MX_TIM2_Init()` 里 `Pulse = 1500`，所以上电默认是 1500。但如果配错成 0，上电就是 0μs，舵机往极限猛转。

`servo_init()` 里先写 CCR 再 `HAL_TIM_PWM_Start()`，就是为了保证**第一个周期就是中位**。

### 11.4 万一还是超了，会有什么现象

| 现象 | 说明 |
|---|---|
| 舵机转到某个角度后"嗡嗡"响不停 | 顶死了，在跟机械限位较劲 |
| 外壳很快发烫 | 堵转，2.5A |
| 松手（断电）后能自由转 | 正常，不是坏了 |
| 断电后转不动 | **齿轮可能已经熔了**，拆开看 |

**听到嗡嗡声立刻断电。**

## 十二、夹爪咬合力怎么控制

### 12.1 核心认知：位置控制 ≠ 力控制

**PWM 舵机只能说"转到哪"，不能说"用多大力"。**

咬合力其实来自**过盈量**：

```
物体宽 40mm
夹爪合到 40mm 位置  → 刚好接触，咬合力 = 0
夹爪合到 38mm 位置  → 多转了 2mm（过盈），靠夹爪/物体的弹性产生咬合力
夹爪合到 30mm 位置  → 过盈 10mm，舵机全力顶，接近堵转
```

**所以"控制咬合力" = "控制目标角度比物体尺寸多转多少"。**

问题在于：舵机没有力反馈，你不知道现在咬多紧。

### 12.2 五种办法，按性价比排

| 方案 | 原理 | 成本 | 推荐度 |
|---|---|---|---|
| **A. 标定过盈量** | 测出"刚好夹住不掉"的角度，固定用它 | 0 | ★★★ 必做 |
| **C. 弹性夹爪** | 指头贴硅胶垫/海绵，用弹性变形吸收过盈 | 10 元 | ★★★ 强烈推荐 |
| D. 两步夹取 | 先合紧，再退 2° 减小咬合力 | 0 | ★★ 可试 |
| B. 电流检测 | 串 0.1Ω 采样电阻，用 ADC 读电流判断 | 5 元 | ★ 后期加 |
| E. 压力传感器 | 指头贴 FSR 薄膜压力片 | 20 元 | ✘ 没必要 |

### 12.3 方案 A 的标定流程（现在就做）

```
1. 上电，发 C 0 让夹爪张开
2. 把 40mm 方块放到两指之间
3. 发 C 1 让夹爪闭合，看夹不夹得住
4. 夹不住（掉） → GRIP_CLOSE_DEG 加 2，重试
5. 夹住了，摸舵机壳：
   - 温热      → ✔ 记下这个角度，写进代码
   - 烫手      → ✘ 咬太紧，退 2° 再试
6. 反复几次找到"夹得住又不烫"的点
```

**代码里改这里：**

```c
#define GRIP_OPEN_DEG    60.0f     // 张开
#define GRIP_CLOSE_DEG  120.0f     // 闭合，按实测改
```

### 12.4 为什么方案 C 值得做

**舵机是刚性连接的**，过盈 1mm 就要靠整个舵机内部齿轮的弹性去吸收，所有力都压在齿轮和电机上。

**指头贴一层 2mm 硅胶**之后：

| | 无硅胶 | 有硅胶 |
|---|---|---|
| 过盈量被谁吸收 | 舵机齿轮（微米级弹性） | 硅胶（毫米级压缩） |
| 舵机需要出的力 | 大 | 小很多 |
| 摩擦系数 | 0.3～0.4（硬塑料） | 0.7～1.0（硅胶） |
| 夹 40mm 方块需要的力 | 0.5N | 0.2N |

**同样的物体，硅胶垫能让舵机少出 60% 的力，还夹得更牢。** 这是最划算的改进。

### 12.5 判断咬合力是否合适的三个办法

| 办法 | 怎么用 |
|---|---|
| **摸温度** | 夹了 30 秒后摸舵机壳，温热正常，烫手就是过紧 |
| **听声音** | 有持续"嗡嗡"声 = 在堵转边缘 |
| **测电流** | 串 0.1Ω 电阻接 ADC，咬合时电流应 < 500mA |

前两个不用任何工具，够用。

### 12.6 一句话总结

**咬合力靠"过盈量"控制，过盈量靠"标定闭合角度"控制，刚性结构靠"硅胶垫"缓冲。**

不要试图用软件"算出"咬合力——舵机没有力反馈，算不出来。
