# 04 · 步进驱动与回零

> 滑台这一路是整个项目里唯一"有物理真值"的轴，也是唯一能搞出丢步、撞机、烧驱动的轴
> 更新时间：2026-11-07

---

## 一、接线（共阳接 3.3V，★ 别接 5V）

```
        3.3V ──┬──────────┬──────────┐
               │          │          │
         驱动器PUL+   驱动器DIR+   驱动器ENA+
               │          │          │
         驱动器PUL−   驱动器DIR−   驱动器ENA−
               │          │          │
            PA8(TIM1)   PB9(GPIO)   PB14(GPIO)
               │          │          │
            拉低=通     拉低=方向    拉低=使能
```

**为什么共阳必须接 3.3V 不能接 5V：**

驱动器的输入端就是一颗光耦的 LED。共阳接法下，MCU 输出**高电平**时两端电压差 = 阳极电压 − 3.3V。

- 共阳接 **5V**：压差 1.7V，光耦 LED **半亮微导通** → 脉冲照发、方向乱跳
- 共阳接 **3.3V**：压差 0V，LED 完全截止 → 干净

**接 3.3V 会不会电流不够？** 光耦 LED 压降约 1.2V，驱动器内部串 220Ω 限流电阻，则电流 = (3.3−1.2)/220 ≈ **9.5mA**，够导通。如果内部是 270Ω（按 5V 设计），只有 7.8mA，也在光耦的导通范围内，但余量小。**装好后量一下 PUL 拉低时 PA8 的灌电流**，正常 5~10mA。

**加上 PA8 上那颗 LED 的 4.2mA**，总共 14mA 左右，PA8 单脚能力 20mA，撑得住。

## 二、脉冲怎么发

**方案：硬件 PWM + 更新中断计数**

```
TIM1: PSC=71 → 1MHz 计数
      ARR = 1,000,000 / f − 1     f = 脉冲频率
      CCR = ARR / 2                固定 50% 占空比
      每次更新中断 = 一个完整脉冲 = 一步 = 0.0025mm
```

**为什么不用"中断里手动翻转 GPIO"：** 20kHz 时每 50μs 一次中断，中断响应抖动会让脉宽忽长忽短，高速时会丢步。硬件 PWM 的脉宽由定时器保证，抖动只有几个 ns。

**为什么不用 "Output Compare 翻转"：** 也能做，但每次翻转都要进中断改 CCR，20kHz 下每 25μs 一次中断，CPU 开销翻倍。PWM 只需要每个周期进一次。

### 2.0 ★ 为什么不用互补 PWM（TIM1_CH1N + 死区）

CubeMX 里 `PWM Generation CH1` 下面还有一个 `PWM Generation CH1 CH1N`，勾上就是**互补输出 + 死区**。**这个不能勾，勾了就错。**

**互补 PWM 是给谁用的：给"功率级"用的，不是给"指令线"用的。**

```
需要互补 PWM 的场景：
  STM32 ──┬── 上管 MOS ──┐
          │              ├── 电机线圈
          └── 下管 MOS ──┘
  上下管不能同时导通（会短路烧管），所以要：
    1. 两路反相（CH1 高时 CH1N 低）
    2. 切换时插一段死区（两路都低），等一个管子真正关断

我们的场景：
  STM32 ──PUL/DIR/ENA──→ 驱动器内部逻辑 ──→ 驱动器内部 H 桥 ──→ 电机线圈
                                              ↑ 互补和死区在这里面，早就做好了
```

**我们给驱动器的是"数字指令"（走一步 / 换方向 / 使能），不是功率波形。**

驱动器内部有：
- 脉冲分配器（把 PUL 转成 A/B 两相的相位序列）
- 双 H 桥（4 个 MOS 管）
- 斩波恒流控制（用 24V 高压 + PWM 斩波来维持线圈电流恒定）
- 死区、过流保护、过热保护

**这些全都做完了，我们只管发脉冲。**

| 场景 | 需要互补 + 死区吗 |
|---|---|
| MCU 直连 MOS 管搭 H 桥 | ✔ 需要 |
| 驱动 BLDC（三相全桥） | ✔ 需要（三对） |
| **驱动成品步进驱动器（PUL/DIR）** | **✘ 不需要** |
| 驱动舵机（单根信号线） | ✘ 不需要 |
| 调光 LED / 加热丝 | ✘ 不需要 |

**判据：MCU 和电感负载之间只要隔着一个功率级（驱动器），就不需要互补。**

### 2.0.1 勾了 CH1N 会有什么后果

1. **PB13 会输出一路反相脉冲**（TIM1_CH1N 在 PB13）。这个脚在中控板上接着 SW3 按键，多一路反转信号过去没好处
2. **死区时间会削减有效脉宽**。死区是"两路都低"的时间，会导致实际高电平变窄。驱动器要求脉宽 ≥ 2.5μs，我们 12kHz 时是 41μs，虽然够，但纯属自找麻烦
3. **停止逻辑变复杂**。单路 PWM 停的时候 `CCR=0` 就恒低了；互补的两路要各自处理

**结论：单路 CH1 就是正确做法，不用互补。**

### 2.0.2 为什么非用 TIM1 不可（不是因为它是高级定时器）

**是引脚决定的，不是功能决定的。**

PA8 这个脚在 F103 上只能复用成 **TIM1_CH1**，没有第二个定时器映射到它。

```
PA8 的复用功能：TIM1_CH1 / MCO / USART1_CK / I2C1_SCL(重映射)
```

而 TIM2/TIM3/TIM4 的 CH1 分别在 PA0/PA6/PB6，全被舵机占了。

所以"用 TIM1"不是因为它高级，是**只有它能出 PA8**。同理舵机用 TIM2/TIM4 也是引脚决定的。

> **顺手说一句：** TIM1 挂在 APB2（72MHz），TIM2/TIM4 挂 APB1（36MHz，但定时器时钟自动 ×2 = 72MHz）。所以所有定时器的计数频率完全一样，`PSC=71 → 1MHz` 对四个定时器通用。

### 2.1 停止的正确写法

```c
// 停：把比较值清 0，PWM 继续跑，但输出恒低，光耦不导通
__HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, 0);
__HAL_TIM_DISABLE_IT(&htim1, TIM_IT_UPDATE);   // 关更新中断，止住计数

// 不要用 HAL_TIM_PWM_Stop()
// 它会把 PA8 从 AF 输出切回悬空，电平不确定，可能残留在高电平
// 光耦一直通着 = 驱动器以为一直在收脉冲 = 电机自己跑
```

### 2.2 速度表

| 速度 | 脉冲频率 | ARR | CCR | 200mm 耗时 |
|---|---|---|---|---|
| 1 mm/s（回零试探） | 400 | 2499 | 1249 | 200s（只用短距离） |
| 5 mm/s（回零） | 2000 | 499 | 249 | 40s |
| 20 mm/s（默认） | 8000 | 124 | 62 | 10s |
| 30 mm/s（上限） | 12000 | 82 | 41 | 6.7s |
| 50 mm/s（★ 会失步） | 20000 | 49 | 24 | 4s |

## 三、加减速（梯形）

直接以最高速启动会丢步：电机转子跟不上突变，听到"咔"一声就位错了。

```
频率
  f_max ┤      ┌──────────────┐
        │     /                \
        │    /                  \
  f_min ┤───/                    \───
        └───┴────┴──────────┴────┴──→ 脉冲数
         加速段   匀速段    减速段
         (N脉冲)          (N脉冲)
```

**实现（每个更新中断里算下一个频率）：**

```c
// 假设：加速段和减速段各用 ramp 个脉冲，起停频率 f_min，最高 f_max
if (done < ramp)                                  // 加速段
    f = f_min + (f_max - f_min) * done / ramp;    // 线性升频
else if (done > total - ramp)                     // 减速段
    f = f_min + (f_max - f_min) * (total - done) / ramp;  // 线性降频
else
    f = f_max;                                    // 匀速段

set_speed(f);                                     // 同时改 ARR 和 CCR
```

**`ramp` 取多少：** 起步阶段脉冲最密，`ramp = 200` 个脉冲 ≈ 加速段 0.5mm，够平滑了。太长了浪费时间。

**线性升频 ≠ 恒加速度**，但对这个负载完全够用。真要做恒加速度得按 `v² = v0² + 2as` 算，代码复杂一倍，收益看不见。

## 四、限位中断（PB12 / EXTI12）

```c
// EXTI 下降沿：传感器检测到铁螺丝 → NPN 拉低 → 下降沿
void HAL_GPIO_EXTI_Callback(uint16_t pin)
{
    if (pin == LIMIT_Z_Pin)                        // 只有限位脚才处理
    {
        g_zero_pulse = g_pulse_count;              // ★ 记下"触发那一瞬间"的脉冲数
        __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, 0);  // 立刻停，不等主循环
        g_step_state = STEP_IDLE;                  // 状态机回空闲
    }
}
```

**三个要点：**

1. **`g_zero_pulse` 记的是触发瞬间的计数，不是停下来之后的计数**。触发到停住之间还会走 5~10 个脉冲（惯性 + 中断延迟），差 0.025mm。要是拿"停住的位置"当零点，每次回零误差都不一样。
2. **中断里直接清 CCR 停脉冲**，不要只置标志等主循环处理。主循环可能正在算逆运动学，耽误几毫秒就多走 0.05mm。
3. **TIM1 中断和 EXTI 中断必须同优先级（都是 1）**。同优先级不能互相抢占，读 `g_pulse_count` 时不会被 TIM1 中断改掉。

---

> **★ 阅读提示：本节和 5.1 里的代码是 11-07 的设计稿，变量名和现在的固件不一样。**
> 实际以 `stm32\Arm\User\bsp\step.c` 为准：`g_pulse_count` → `s_pos`（对外 `step_pos_pulse()`）、
> `g_zero_pulse` → 不再单独存（触发瞬间直接把 `s_pos` 清 0，同时把偏移记到 `s_home_offset`）、
> `g_step_state` → `step_is_busy()`、`HOMING_*` → `HOME_*`。

## 五、回零流程（这个顺序不能变）

```
   ① 向上慢速离开      ② 向下寻找          ③ 触发记零点      ④ 向上退开
   ┌─────────┐        ┌─────────┐        ┌─────────┐       ┌─────────┐
   │ 5mm/s   │        │ 5mm/s   │        │ 立刻停  │       │ 5mm/s   │
   │ 走5mm   │        │ 最多220mm│        │zero=cnt │       │ 退3mm   │
   └─────────┘        └─────────┘        └─────────┘       └─────────┘
```

**① 为什么要先向上离开：** 上电时滑块可能就停在传感器上方（或者说，传感器正好被挡住）。此时传感器一直是"触发"状态，直接在原地向下找永远等不到下降沿（它已经是低电平了）。

**② 为什么最多 220mm：** 滑台行程 200mm，滑块到不了两端。走 220mm 还没触发 = 传感器坏了 / 线松了 / 触发体没装，直接报错停机，**别傻走**。

**④ 为什么要退 3mm：** 回零完停在传感器上，下一次回零又检测不到下降沿。退 3mm 让传感器释放，下次能重新触发。

### 5.1 回零状态机

```c
typedef enum {
    HOMING_IDLE = 0,
    HOMING_BACKOFF,      // ① 向上离开
    HOMING_SEEK,         // ② 向下找
    HOMING_RETREAT,      // ④ 退 3mm
    HOMING_DONE,
    HOMING_ERROR,
} HomingState_t;
```

主循环里用 `switch` 推，配合 `g_step_state`（电机是否还在走）判断阶段结束。

**★ 主循环里不许有 `HAL_Delay`。** 所有等待改成查 `g_step_state == STEP_IDLE` 或者查 `HAL_GetTick()` 的时间戳。

### 5.2 ★ 装完传感器的上电自检（第一次回零之前必做）

固件新增 `L` 命令，直接回显 PB12 电平。**不用让电机动，就能验收整条限位链路**：

```
L   →   LIM 0    传感器释放（黑线悬空，内部上拉把 PB12 拉到高）
        LIM 1    传感器触发（黑线被拉到 0V，PB12 下降沿）
```

**★ 第一步：接 MCU 之前，先用万用表判 NPN / PNP**

传感器单独上 24V（棕 → 24V+，蓝 → 24V−），黑线先**不接** STM32。万用表直流档，黑表笔接 24V−，红表笔接黑线：

| 拿铁片靠近传感器的结果 | 型号 | 能不能直接接 PB12 |
|---|---|---|
| 悬空（读数乱飘 / 接近 0）→ **0V** | **NPN 常开**（SN04-N） | ✔ 串 1k 直接接 |
| 悬空（读数乱飘 / 接近 0）→ **24V** | **PNP 常开**（SN04-P） | ✘ 24V 经 1k 灌进 PB12，约 20mA 全压在引脚钳位二极管上，会把 3.3V 轨抬高甚至烧脚。必须加分压（如 10k+3.3k）或换型号 |

★ 这一分钟能省一块核心板。**别指望 1k 电阻能挡住 24V。**

**★ 但 NPN 常开其实可以不串电阻，直连就行**（11-16 确认）：开集电极输出，黑线只连三极管集电极，**物理上没有通向 24V 的路径**——导通拉 0V、截止悬空靠内部上拉。器件击穿的结果是"永久拉低"（一直触发），也不是灌 24V。
真正的风险只有**棕/黑接反**（24V 直接进引脚），所以重点是接线前反复核对颜色，而不是加电阻。串 1k~4.7k 只是额外保险，手头没有可以省。

**第二步：串口自检**

1. 按第六节接线（棕 → 24V、蓝 → GND、黑 → 串 1k → PB12），上电
2. 发 `L`，拿 M4 螺丝靠近传感器 4mm 以内再拿开：

| 回显 | 结论 |
|---|---|
| 靠近变 `LIM 1`、拿开变 `LIM 0` | ✔ 接线正确，可以装到滑台上 |
| 一直 `LIM 0` | 上拉正常但传感器没通 → 查 24V 供电、黑线断、传感器坏 |
| 一直 `LIM 1` | 黑线被拉死在 0V → 查短路、查是不是碰到 GND |
| 靠很近才偶尔变一下 | 检测距离不够，铁要 4mm 内、铝只有 2.4~2.8mm |

**第三步：装到滑台上再确认一次**

传感器移到滑台最底部、M4 铁螺丝头朝下拧在夹板上、间隙调 3mm 之后，手动把滑块压到底，发 `L` 必须是 `LIM 1`；抬起来 5mm 必须是 `LIM 0`。两个状态都要有，缺一个就是间隙不对。

## 六、验收判据

### 6.1 回零重复性（最关键）

固件每次回零完成会打印一行：

```
HOME DONE Z0 -1200
              ↑ 触发点相对"本次回零起点"的脉冲偏移（1 脉冲 = 0.0025mm）
```

**测法：连着发 10 次 `H`，把这 10 个数字抄下来。**

- 回零之间**不要用 `T` 移动滑块**，否则起点变了，数字没法互相比
- 第一次的数字没意义（上电位置随机），从第二次开始比
- 理论上应该恒定在 **−1200 附近**（向上 5mm = +2000 脉冲，再向下 8mm 到触发点 = −3200 脉冲）

看 10 个数的**极差（最大值 − 最小值）**：

| 极差 | 结论 | 对策 |
|---|---|---|
| ±5 脉冲（±0.0125mm） | 完美 | 不用管 |
| ±40 脉冲（±0.1mm） | 能用 | 查 M4 螺丝松没松、触发体晃不晃 |
| 几百脉冲 | 不能用 | 间隙卡在 3~4mm 边缘，调到 2.5mm 再试 |
| 单调漂移（每次都往一边跑） | 传感器或触发体在动 | 紧固，别用胶粘 |

★ 数字整体偏离 −1200 但**不乱跳**（比如稳定在 −800）：说明 BACKOFF 那段实际没走够 5mm，或中途丢步，先降速再测，别急着改传感器。

### 6.2 丢步检查

用 `T` 走相对距离（相对移动不受软上限限制）：

```
T 60 4000      向上 60mm，4000Hz ≈ 10mm/s（11-16 实测这个频率声音最实）
T -60 4000     再走回来
S              看 Z 回到 0 附近没有
```

| 现象 | 原因 |
|---|---|
| 回到 0 的 ±30 脉冲以内（±0.075mm） | 正常（齿隙） |
| 偏出 200 脉冲以上（0.5mm） | 丢步，降速或加细分 |
| 每次来回越偏越多 | 频率太高，或者 24V 电源撑不住 |

## 七、编码器（★ 型号已确认，可以接）

### 7.1 实物信息（主人 11-07 拍照）

| 项 | 值 |
|---|---|
| 品牌 | ROTAY ENCODER |
| 型号 | **E38D6G5-600-G24N** |
| 供电 | **DC 5~24V** |
| 分辨率 | **600 PPR**（每转 600 个脉冲，A/B 正交） |
| 输出相 | **只有 A、B 两相，没有 Z 相** |
| 线色 | 红=Vcc，黑=0V，**白=A，绿=B** |
| 出线数 | **4 根**（排母 6 个口只用了 4 个，另 2 个空的是给 Z 相和屏蔽留的） |
| 外径 | 38mm |

**结论：这是增量式旋转编码器，装在丝杆末端（电机另一侧）。**

### 7.2 能给什么

```
丝杆导程 4mm，编码器 600 PPR
单相计数：1200 脉冲/转   →  4mm ÷ 1200 = 0.0033mm
四倍频：  2400 计数/转   →  4mm ÷ 2400 = 0.00167mm
```

比步进开环的 0.0025mm/脉冲还细。

### 7.3 ★ 但它救不了你，别指望闭环

| 想做的事 | 编码器能不能 |
|---|---|
| **发现丢步**（走了 100mm，实际只走 98mm） | ✔ 能，这是它最大的价值 |
| 断电后知道滑块在哪 | ✘ **没有 Z 相，上电不知道绝对位置**，还是要回零 |
| 完全闭环控制（位置环 PID） | ✘ A/B 相只能测速和增量位置，做闭环还要处理换向抖动，工作量很大 |

**所以定位不变：第一版不用它，回零照样要做。**

### 7.4 接线方案（★ NPN 输出必须这样接）

`G24N` 里的 **N** 表示 **NPN 集电极开路输出**（开漏）。意思是：

- 输出低：晶体管导通，把线拉到 **0V**（能灌电流）
- 输出高：晶体管截止，线**悬空**（必须靠外部上拉才有高电平）

**直接接 STM32 是收不到高电平的**，必须加上拉电阻。

```
编码器 红(Vcc) ── 5V      ★ 接 5V，不要接 24V（虽然支持，但没必要冒风险）
编码器 黑(0V)  ── GND     ★ 和 STM32 共地

编码器 白(A) ──┬── 4.7kΩ ── 3.3V
               └── 1kΩ ──── PB4（TIM3_CH1）

编码器 绿(B) ──┬── 4.7kΩ ── 3.3V
               └── 1kΩ ──── PB5（TIM3_CH2）
```

**为什么串 1kΩ：**
- 上拉放在**编码器那一侧**（不是 MCU 侧），编码器拉低时 MCU 脚干净地到 0V
- 万一这编码器实际是推挽输出（5V 推挽），1kΩ 把灌进 MCU 的电流限到 (5−3.3−0.7)/1000 ≈ **1mA**，不会烧
- 串了 1k 之后上升沿会慢一点，600 PPR 下最高脉冲频率不到 10kHz，完全够

**为什么 Vcc 接 5V 不接 3.3V：** 标签写 5~24V，3.3V 不在范围内，可能不转。

**★ 上拉一定要接 3.3V 不是 5V。** 上拉接 5V 的话高电平 5V 直接灌进 PB4/PB5。

### 7.5 怎么用（如果接）

TIM3 编码器模式，CubeMX 里配：
- `Timers` → `TIM3` → `Combined Channels` → **Encoder Mode**
- Channel1/Channel2 都设 Input
- `Encoder Mode` = **TI1 and TI2**（四倍频）
- `Polarity` = Rising Edge
- `Input Filter` = 6~10（滤掉丝杆传过来的抖动）

然后 `__HAL_TIM_GET_COUNTER(&htim3)` 读计数。

**TIM3 的 CNT 是 16 位，会溢出。** 要在更新中断里累加，或者定期读差值。

### 7.6 我的建议

**先接上，但第一版代码不依赖它。**

理由：接线就 4 根线 + 2 个电阻，5 分钟的活。接上之后调试时能随时读"编码器说走了多少 vs 我以为走了多少"，丢步一眼就看出来。真出问题时这一个数能省半天。

但**定位仍然靠限位回零**，编码器只当"验尸报告"用。
