# 10 · 腕转姿态解耦：让平行夹爪在任意位置保持固定朝向

> 这个问题不做，机械臂就永远抓不稳方块。而且它藏得很深——单看某一个位置，一切正常。

## 一、现象

机械臂在待机位（两臂收拢）时，夹爪朝向是**平行于 X 轴**的。手动把指令发到 `M 100 0`（沿 X 轴伸出 100mm），
夹爪变成**垂直于 X 轴**了。再走到 `M 200 0`，又歪了 33°。

指令里从头到尾没改过腕转角，它一直是 85°。

| 位置 | θ1+θ2（小臂绝对角） | 腕转指令角 | 夹爪绝对朝向 |
|---|---|---|---|
| 待机（r=35） | −180° | 85° | **0°**（平行 X） |
| `M 100 0` | −91.5° | 85° | **88°**（垂直 X） |
| `M 200 0` | −57.1° | 85° | **123°**（歪 33°） |

夹爪朝向随位置一路漂移，抓方块时必然夹到棱角，一夹就掉。

## 二、原因

腕转舵机**装在小臂末端**，它转角是相对于小臂的。而 SCARA 的 `M`/`P` 命令只动大臂和小臂，
腕转指令保持不变 —— 小臂的绝对角变了，夹爪的绝对朝向就跟着变。

```
夹爪绝对朝向 = 小臂绝对角(θ1+θ2) + 腕转带来的附加转角
```

这是个纯几何的耦合，不是 bug，是 SCARA 这种构型的固有性质。任何带独立腕转轴的平面机械臂都会遇到。

## 三、解法：把「朝向」当输入，反解腕转角

不要试图「试出一个固定腕转角」——换位置就得重来。正确做法是把夹爪的**绝对朝向**当目标值：

```
夹爪绝对朝向 A = (θ1 + θ2) − 腕转角 + C
```

### 三个关键点

**1. 是减号，不是加号**

腕转脉宽变大，夹爪绝对角反而变小。方向与直觉相反。

**2. C 是实测标定出来的，不是算出来的**

因为腕转舵机的实际中位安装角、齿轮装配误差、脉宽-角度增益都含在这个常数里。
标定方法：**在几个不同的位置，手动调腕转直到夹爪目测垂直 X 轴，记下脉宽**，反推 C：

| 位置 | θ1+θ2 | 手动调到的脉宽 | 反推 C |
|---|---|---|---|
| `M 100 0` | −91.5° | 1472μs（86.6°） | 268.1 |
| `M 150 0` | −73.0° | 1650μs（102.5°） | 265.5 |
| `M 200 0` | −57.1° | 1800μs（115.8°） | 263.0 |
| `M 250 0` | −39.9° | 2000μs（133.7°） | 263.5 |

取 **C = 265**，残差 ±3°。代回待机位那组数据（θ1+θ2 = −180°）算出腕转 85.0°，
和独立标定出来的「待机时腕转 85°」完全一致 —— 模型自洽。

**3. 平行爪有 180° 对称，负角度不是无解**

反解结果可能落在 `[0,180)` 之外。但**平行爪转 180° 形状完全一样**（只是开口朝向反过来），
所以一律 `+180` 折回行程内，永远不会出现「这个位置无解」。

## 四、代码

```c
// kinematics.h
#define WRIST_ABS_OFFSET_DEG      265.0f   // A = (θ1+θ2) − 腕转角 + 265
#define WRIST_ABS_PARALLEL_X        0.0f   // 平行 X（待机用）
#define WRIST_ABS_PERPENDICULAR_X  90.0f   // 垂直 X（作业默认）

// kinematics.c
float wrist_deg_for_abs(float theta1_deg, float theta2_deg, float target_abs_deg)
{
    float w = (theta1_deg + theta2_deg) + WRIST_ABS_OFFSET_DEG - target_abs_deg;

    while (w <    0.0f) w += 180.0f;      // 平行爪 180° 对称，折回行程内
    while (w >= 180.0f) w -= 180.0f;

    return w;
}
```

在 `M` / `P` 命令里，逆解算完 θ1、θ2 之后自动下发：

```c
servo_move_deg(SERVO_WRIST,
               wrist_deg_for_abs(j.theta1_deg, j.theta2_deg,
                                 WRIST_ABS_PERPENDICULAR_X), 3.0f);
```

## 五、验证

发五个点，每个都 `S` 一次读回腕转角：

| 命令 | θ1+θ2 | 公式算出的腕转 | 实测腕转 | 夹爪朝向 |
|---|---|---|---|---|
| `M 50 0` | −127.4° | 47.6° | **47** | 视觉一致 |
| `M 100 0` | −91.5° | 83.5° | **83** | 视觉一致 |
| `M 150 0` | −73.0° | 102.0° | **101** | 视觉一致 |
| `M 200 0` | −57.1° | 117.9° | **117** | 视觉一致 |
| `M 250 0` | −39.9° | 135.2° | **135** | 视觉一致 |

★ **判据：绝对朝向是不是正好 90° 不重要，各个半径上一致才重要。**
平行爪夹方块，只要每个位置朝向一致，5° 的整体偏差完全不影响抓取。

## 六、这个坑教了什么

### 单点标定定不了方向

第一版只用了**待机位一个点**反推，公式写成了 `+腕转角 + 95`。

为什么一个点看不出来：θ1+θ2 = −180° 时，
`w = target − (θ1+θ2) − 95` 和 `w = (θ1+θ2) + 265 − target` **两种符号都能凑出 175°**。
一个点只能验证「这个位置对不对」，定不了「关系怎么走」。

多测的 `M 150 / 200 / 250` 三个点才把符号钉死：腕转从 85° 一路涨到 134°，
而夹爪要保持 90° 不变，说明两者是负相关。

**方法论：标定任何两个量之间的线性关系，至少取两个点定符号，三个点以上定偏置。**

### y 方向变化不需要重新标定

公式吃的是 θ1+θ2，逆解对任何 (x,y) 都给得出。同一份代码、同一个 C，
`M 150 0`（腕转 102°）和 `M 150 100`（腕转 145°）都能保持夹爪垂直 —— 只是自动算出的腕转角不同。

### 但 y 太大会触发 180° 折叠

`y` 往正向走得远时（如 `M 100 200`），θ1+θ2 变正，算出的腕转超过 180°，折回后落到 0～20°。
**夹爪仍然是垂直的**，但开口朝向反了 180°。方形物体无所谓，要从固定一侧夹就得限制 y 范围。
