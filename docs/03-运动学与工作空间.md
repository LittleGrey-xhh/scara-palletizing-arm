## 一、逆解公式（就是余弦定理，没有 DH、没有矩阵）

平面二连杆，末端坐标 (x, y)，两臂长 L1、L2：

```
r² = x² + y²

cos(θ2) = (r² − L1² − L2²) / (2·L1·L2)
θ2 = ±acos( cos(θ2) )                     ← 正负号 = 两组解（肘上 / 肘下）

θ1 = atan2(y, x) − atan2( L2·sin θ2 , L1 + L2·cos θ2 )
```

**就这三行。** 六个自由度才需要 DH 参数和雅可比矩阵，平面两连杆用不着。

**正解**（验证用，也是算"当前末端在哪"）：

```
x = L1·cos θ1 + L2·cos(θ1 + θ2)
y = L1·sin θ1 + L2·sin(θ1 + θ2)
```

## 三、★ 工作空间的真实形状：斜扇环（不是圆盘，也不是正扇环）

### 3.1 先纠正一个容易搞混的地方：θ1 的范围 ≠ 末端方位角

一开始我把"大臂舵机能转 ±82°"直接当成了"末端方位角只有 ±82°"，这是错的。

等长臂（L1 = L2 = L）时，把正解展开：

```
x = L[cos θ1 + cos(θ1+θ2)]
y = L[sin θ1 + sin(θ1+θ2)]
```

用和差化积：

```
cos A + cos B = 2·cos((A+B)/2)·cos((A−B)/2)
sin A + sin B = 2·sin((A+B)/2)·cos((A−B)/2)
```

代入 A = θ1、B = θ1+θ2：

```
r = 2L·cos(θ2/2)              ← 半径只由 θ2 决定
φ = θ1 + θ2/2                 ← ★ 末端方位角 = 大臂角 + 半个小臂角
```

**所以末端方位角的跨度确实等于 θ1 的跨度（164°），但整个区间被 θ2/2 推着走。**

这就是为什么"单圈能扫 164°"和"工作区不是正扇环"两件事同时成立。

### 3.2 实测数据（`test_kinematics.c` 第 3 节）

| r (mm) | θ2 (°) | φ 中心 (°) | φ 范围 (°) |
|---|---|---|---|
| 20 | 171.6 | 85.8 | 3.8 ~ 167.8 |
| 60 | 154.7 | 77.4 | 355.4 ~ 159.4 |
| 100 | 137.2 | 68.6 | 346.6 ~ 150.6 |
| 150 | 113.6 | 56.8 | 334.8 ~ 138.8 |
| 200 | 86.2 | 43.1 | 321.1 ~ 125.1 |
| 250 | 48.3 | 24.2 | 302.2 ~ 106.2 |
| 270 | 19.6 | 9.8 | 287.8 ~ 91.8 |

**每条弧的跨度都是 164°，但中心从 85.8° 一路漂到 9.8°，漂了 76°。**

画出来就是一片"扭过的扇形"——内圈偏向左边，外圈偏向前方。

### 3.3 结论

| 项目 | 真实值 | 说明 |
|---|---|---|
| 最大半径 | **274mm** | 两臂伸直，数学上限 |
| 最小半径 | **约 20mm** | 数学上能到，机械上两臂会撞，实际 120mm 起 |
| **单半径方位覆盖** | **164°** | ★ 舵机行程的硬限制，不是全向 360° |
| **φ 中心漂移** | **76°**（内圈 86° → 外圈 10°） | ★ 这是"斜扇环"的来源 |
| **全半径公共方位** | **118°**（φ ∈ [−18°, 100°]） | r ∈ [120,260] 时所有半径都能到的交集 |
| 工作区形状 | **斜扇环** | 不是圆盘，也不是规则扇形 |

### 3.4 为什么是 164° 不是 180°

代码里 `SERVO1_MIN_DEG = 8` / `SERVO1_MAX_DEG = 172`，两头各留 8° 安全余量，防止顶死舵机。

**这 8° 余量不能省。** 顶到 0°/180° 的后果是嗡嗡响、发热、烧掉。宁可少 16° 的工作范围。

### 3.5 这个结论怎么用

| 想做什么 | 能不能 |
|---|---|
| 物体摆在臂前方一片连续区域 | ✔ 够用，164° 比预想的宽 |
| 物体绕臂一圈 360° 摆 | ✘ 得在底座再加一个回转舵机 |
| 抓臂正下方（r < 100mm） | ✘ 两臂会撞 |
| 桌面画一块矩形工作区 | ✔ 取公共区间 φ ∈ [−18°, 100°]、r ∈ [120, 260] |

**建议工作区：`r ∈ [120, 260] mm`，`φ ∈ [−18°, 100°]`（118°）**

面积 = 0.5 × (118° 转弧度) × (260² − 120²) ≈ **550 cm²**

**★ 装配时要注意 φ 的偏置：** 大臂中位若对准 +X（`THETA1_HOME = 0`），实际工作区整体偏向 +Y（左侧）—— 因为 φ = θ1 + θ2/2，θ2/2 恒为正。

想让工作区居中，把 `THETA1_HOME` 设成 **−40° ~ −50°**（大臂中位略偏右前），这样 φ 中心落在 0 附近。或者干脆装配时把底座整体转个角度。

换算成长方形大约是 25cm × 26cm 的一片，摆 3×4 个 40mm 积木方块绰绰有余。

## 四、和工业码垛机器人比，为什么行程差这么多

主人给的参照是 **WS-04 立柱式码垛机器人**：

| 项目 | WS-04 | 我们的 | 倍数 |
|---|---|---|---|
| 轴数 | **4** | 3（+夹爪） | — |
| 1 轴 | 立柱升降 1300~2500mm | Z 轴 0~200mm | 1/10 |
| 2 轴 | **腰部回转 +135° ~ −120°（255°）** | **θ1 回转 164°** | 1/1.6 |
| 3 轴 | **大臂俯仰 ±165°** | θ2 折叠 0~180° | — |
| 4 轴 | **腕部回转 ±360°（连续）** | 无 | — |
| 工作半径 | 2000~2400mm | 120~260mm | 1/10 |
| 速度 | 1000mm/s、98°/s | 30mm/s、75°/s | 1/30 |
| 重复精度 | ±0.5mm | ±2~5mm | 1/8 |
| 负载 | 35~150kg | 约 0.1kg | 1/1000 |
| 自重 | 700kg | 约 1kg | 1/700 |

### 4.1 差在三件事上，不是"设计得不好"

**第一件：构型完全不同**

```
WS-04（立柱式）：          我们（SCARA）：
  立柱上下升降             滑台上下升降
    ↓                        ↓
  腰部绕立柱回转 255°       大臂水平回转 164°
    ↓                        ↓
  大臂垂直面内俯仰 ±165°    小臂水平面内折叠 0~180°
    ↓                        ↓
  腕部回转 ±360°            夹爪（只能开合）
```

WS-04 的 2 轴是**绕立柱转整个身子**（像人转身），3 轴是**抬手**，4 轴是**转手腕**。
我们是**两臂在桌面上平铺**，靠折叠够到不同位置。

**第二件：执行器差两个数量级**

| | WS-04 | 我们 |
|---|---|---|
| 驱动 | 交流伺服电机 + 谐波/行星减速机 | 航模舵机 MG996R |
| 角度反馈 | 绝对值编码器（17~23 位） | **无，纯开环** |
| 限位 | 软件 + 硬限位开关，**无物理死点** | **舵机内部有机械限位，180° 到头** |
| 单轴成本 | 几千到上万 | 15 元 |

**★ 我们只有 180°，根本原因不是"算错了"，是舵机这玩意儿物理上就只能转 180°。** 拆开看：舵机里是一颗电位器做位置反馈，电位器的有效行程就 270°，厂家卡到 180° 保证线性度。想让它连续转，得把电位器换成"只输出中值"的假反馈——那就变成"连续旋转舵机"，只能调速不能定位，等于废掉。

**第三件：量级差 1000 倍**
700kg 的铸铁底座 vs 1kg 的铝板+3D 打印件。工业机器人靠自重和刚性抗弯矩，我们只能靠缩短臂长。

### 4.2 想把行程做大，四条路

| 方案 | 能到多少 | 成本 | 工作量 | 值不值 |
|---|---|---|---|---|
| **保持现状** | 164° / 260mm | 0 | 0 | ✔ 分拣演示够用 |
| 舵机换"连续旋转舵机" | 360° 但**不能定位** | 20 元/个 | 1 小时 | ✘ 等于自废武功 |
| **底座加第 5 轴**（步进 + 减速） | 360° 有定位 | 100~150 元 | 3~5 天 | 后期加分项 |
| θ1 换步进 + 同步带 | 360° + 精度提升到 ±1mm | 150~200 元 | 一周 | 时间不允许 |

**结论：先按 164° 做，跑通再考虑加第 5 轴。**

理由是 164° 对"桌面上摆一排方块分拣"完全够——摄像头视野一般也就 60° 左右，164° 已经把视野包进去了。**真正限制演示效果的是精度（±3~5mm）和 Z 轴速度（20mm/s），不是角度。**

## 四、两组解怎么选

`ik_solve(x, y, elbow, &j)` 的第三个参数：

| elbow | θ2 符号 | 姿态 | 什么时候用 |
|---|---|---|---|
| **+1** | 正（0~180°） | 小臂折向左（逆时针侧） | **默认用这个** |
| −1 | 负（−180~0°） | 小臂折向右 | 本机舵机行程只覆盖正侧，用不了 |

**为什么只留一组：** 小臂舵机 1500μs 对应 θ2 = 90°，行程 0~180° 只能转出 θ2 ∈ [0, 180]。θ2 想取负值就要舵机转到 −50° 之类，超出机械限位。

等长臂的两组解是镜像对称的，抓取效果完全一样。舍掉一组只损失"多一条绕行路径"，**不影响能不能抓到**。

## 五、精度能到多少（别抱太高期望）

| 误差源 | 量级 | 说明 |
|---|---|---|
| PWM 分辨率 | 0.09° | 1μs ÷ 11.11μs每度，定时器 1MHz 计数 |
| **舵机死区** | **0.36°** | 厂家标 4μs（数字舵机），脉宽变化小于这个舵机不动 |
| **齿轮间隙** | **0.5~1.5°** | MG996R 金属齿，来回转有回差 |
| 舵机重复定位 | ±1~2° | 同一脉宽来回走，落点不固定 |
| **末端综合** | **±3~5mm @ 250mm 处** | 1° ≈ 4.4mm，全是角度误差放大的 |

**结论：纯舵机开环，250mm 处末端误差 3~5mm，抓 40mm 的积木够用，抓 10mm 的小件就要视觉补偿。**

这也解释了为什么交接文档把 ArUco 末端视觉补偿放在 P2 —— 不是锦上添花，是精度不够时的后手。

**装的时候能省一点是一点：**
- 齿轮间隙是最大头，**装配时让常用姿态落在"往一个方向转过去"的位置**，别来回抖
- 每次定位都从同一个方向靠近（比如总是顺时针转到目标角），回差被固定住就好补偿

## 六、Z 轴速度是隐藏的坑

```
脉冲当量 4mm ÷ 1600 = 0.0025mm/脉冲
```

| 速度 | 脉冲频率 | 200mm 行程耗时 |
|---|---|---|
| 20 mm/s | 8 kHz | **10 秒** |
| 30 mm/s | 12 kHz | 6.7 秒 |
| 50 mm/s | 20 kHz | 4 秒 |

**50mm/s 对应的电机转速是 750 RPM**（50 ÷ 4 × 60），42 步进 + T8 丝杆在 24V / 0.5A 下大概率失步，实测临界点一般在 300~500 RPM（20~33mm/s）。

**所以 Z 轴现实速度是 20~30mm/s。**

**对策：缩短 Z 行程。** 分拣演示不需要 200mm 全行程，抓取和放置的高度差 50~80mm 就够，那 2~4 秒能接受。

代码里 `step_run()` 的速度上限设 30mm/s（12000 脉冲/s），别贪快。

### 6.1 顺带算一下舵机要多久

厂家标 0.17s/60°（4.8V）= **353°/s**：

| 动作 | 角度 | 全速耗时 | 按 50% 速度（推荐） |
|---|---|---|---|
| 小臂折转 | 30° | 0.09s | 0.17s |
| 大臂摆动 | 60° | 0.17s | 0.34s |
| 大臂摆动 | 90° | 0.26s | 0.51s |

**别用全速。** 全速启动会让整个臂甩出去，末端定位全靠猜。`servo_move_deg()` 里 `deg_per_tick` 按 20ms 一拍算：

```
每拍走 1.5°  →  75°/s  →  90° 要 1.2 秒
每拍走 3.0°  →  150°/s →  90° 要 0.6 秒
```

**一个完整的抓取循环（下降 → 夹 → 抬起 → 平移 → 下降 → 松 → 抬起）大概 8~12 秒**，演示时按这个排节奏。

## 八、串口协议里的坐标约定

上位机（PC / 树莓派）发目标点，统一用这套：

```
X 轴：正前方，单位 mm
Y 轴：正左方，单位 mm
Z 轴：向上为正，单位 mm，零点 = 滑台最底下的限位触发点
θ   ：绕 Z 轴转，0° = 夹爪朝 +X，逆时针为正
```

**为什么 Z 零点在限位点而不是"最上面"：** 限位是唯一有物理真值的参考。滑台走到限位，`g_pulse_count` 记下的值就是零点，之后所有 Z 坐标都是"零点往上多少 mm"，不依赖上电时的位置。

**上电必须回零**，否则 Z 坐标全是瞎的。
